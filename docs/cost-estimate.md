# Omnixa V1 月度成本估算

> 目标：给出单 VPS 部署（方案 A）的月度成本区间，并对比「云托管 MySQL/Redis」「LLM 按量调用」「备份存储」的可选增量。
> 口径说明：以下为**估算区间**（人民币为主，附美元参考），价格随云厂商、地区、折扣、汇率浮动，落地前请以厂商实时报价为准。假设 Classroom Beta 规模为**数十到数百名用户、中等并发、日常轻中度使用**。

---

## 1. 单 VPS（核心支出，方案 A 推荐）

| 规格 | 适用 | 月度成本区间（估算） |
| --- | --- | --- |
| **最低：2 vCPU / 4GB 内存 / 40GB SSD** | 最小可用（MySQL+Redis+backend+worker+frontend+nginx 全跑一台，低并发） | 约 **¥30–120/月**（$5–17；国内轻量应用服务器 2C4G 常在 ¥50–100，海外 Hetzner CX22 ≈ €4.5） |
| **推荐：2 vCPU / 8GB 内存 / 60–80GB SSD** | 留出 MySQL InnoDB buffer + 并发流式 + 突发上传余量 | 约 **¥80–250/月**（$12–35） |
| 4 vCPU / 8–16GB（弹性扩容档） | 高并发/大知识库/多副本 worker | 约 **¥200–500/月**（$30–70） |

> RC1 容量基线参考（`docs/classroom-beta-rc1-report.md` §G）：chat 10/20/30 并发在本机 MySQL（连接池 10+20）可全成功，P95 ~ 1s；瓶颈在 MySQL 默认连接池而非 CPU。故**推荐档（2C8G）对 Classroom Beta 足够**，不建议一上来就 4C。

---

## 2. MySQL / Redis：自建 vs 云托管

| 方案 | 月度成本区间 | 说明 |
| --- | --- | --- |
| **自建（随 VPS，推荐）** | **¥0 增量**（含在 VPS 里） | `docker-compose.yml` 内置 mysql:8.4 + redis:7.4，数据落 `mysql-data`/`redis-data` 卷；Beta 阶段最省 |
| 云托管 MySQL（RDS 8.0 基础版 2C4G 通用型） | 约 **¥150–400/月** | 免运维、自动备份/高可用，但显著拉高成本 |
| 云托管 Redis（1GB 标准版） | 约 **¥30–100/月** | 免运维；但本项目 Redis 仅存 RQ 队列+lease（可重建），云托管性价比低 |

> 结论：**Beta/收口阶段强烈建议自建**（与 VPS 同机）。只有当 VPS 内存吃紧或需要高可用时才考虑云托管；届时增量约 **¥200–500/月**（MySQL+Redis 合计）。

---

## 3. LLM / Embedding / Vision 按量调用

> 变量最大的一项，取决于：提供方、模型档位、token 单价、日活、每次对话 token 量、RAG 检索量、图片调用量。

| 场景 | 月度成本区间（估算） | 假设 |
| --- | --- | --- |
| **演示/mock 模式** | **¥0** | `LLM_PROVIDER_LABEL=mock`，离线 canned 响应（仅演示，非生产） |
| **轻量真实使用（数十用户，每日少量对话）** | 约 **¥50–500/月** | 国产 OpenAI-compatible 模型（文本+embedding），按量计费 |
| **中等真实使用（百级用户，含 RAG + 视觉）** | 约 **¥200–2000/月** | 含视觉模型按图调用；RAG 每问一次检索+生成 |
| 重度/无节制调用 | 上不封顶 | 需靠积分计费（`CREDIT_INPUT_RATE`/`CREDIT_OUTPUT_RATE`）+ 限流兜底 |

> 控制手段：系统已内置积分计费（`billing.py` 幂等记账）与限流（`RATE_LIMIT_*`）；`INVITE_REQUIRED=true` + `REFERRAL_*=0` 防止刷量。视觉单价高，建议 `VISION_BASE_CREDIT_COST` 设保底值并限制图片数（`MAX_CHAT_IMAGES_PER_*`）。

---

## 4. 备份存储

| 方案 | 月度成本区间 | 说明 |
| --- | --- | --- |
| **随 VPS 本地盘 + 定期快照** | **¥0–10/月** | `mysqldump` + uploads 压缩（`docs/backup-restore.md`）；Beta 数据量小（约 1–5GB） |
| 对象存储（OSS/COS/S3，异地备份，推荐） | 约 **¥1–20/月** | 标准存储 + 少量请求；异地容灾更稳 |
| 云厂商磁盘快照（按需） | 约 **¥5–30/月** | 每 GB 快照单价低，按卷容量计 |

> 建议：生产至少「本地自动备份 + 异地对象存储」双份，成本基本可忽略（<¥20/月）。

---

## 5. 总成本区间汇总（月度）

| 部署形态 | 最低 | 推荐 | 说明 |
| --- | --- | --- | --- |
| **A. 单 VPS 全自建 + mock LLM（演示）** | ≈ **¥30–120** | ≈ **¥80–250** | 仅 VPS，无云托管、无 LLM 调用 |
| **B. 单 VPS 全自建 + 真实 LLM（轻量真实使用）** | ≈ **¥80–620** | ≈ **¥160–750** | VPS + LLM ¥50–500 |
| **C. VPS + 云托管 MySQL/Redis + 真实 LLM（中量）** | ≈ **¥330–1020** | ≈ **¥450–2250** | 再加云托管 ¥200–500 |

> 一句话结论：**Classroom Beta 收口阶段推荐「方案 B 中间档」——2C8G VPS + 自建 MySQL/Redis + 真实 LLM 按量，月度预算约 ¥160–750**，其中 LLM 是最大可变项，建议按月盯账单并配告警。

---

## 6. 降本建议

1. **自建 MySQL/Redis**（本方案 A 已内置），Beta 阶段不买云托管。
2. **视觉默认走较便宜档位**，并限制图片数量与保底扣费。
3. **限流 + 积分计费**已内置，务必保持 `INVITE_REQUIRED=true`、`REFERRAL_*=0` 防止刷量。
4. **备份用「本地 + 对象存储」双份**，成本几乎为零，避免数据事故的隐性成本。
5. 若调用量上不去，优先优化 `RAG_MAX_CONTEXT_CHARS` / 分块参数减少 token，而非扩机。
